# Hong Kong gym data imports

This directory contains data generated by `scripts/gyms/import-*.mjs` and manual override files. Run all commands below from the repository root after installing dependencies with `pnpm install`.

## Quick start

By default, importers fetch data from source websites/APIs, convert it into Gymory gym rows, and write JSON **without writing to Supabase**. A dry run still accesses the network and overwrites the output file; use `--out` to select another location for previews.

```bash
# Fetch a small sample and inspect the JSON.
pnpm import:anytime-fitness-hk --limit 2 --out /tmp/anytime-preview.json

# Fetch the complete dataset and write the default baseline.
pnpm import:anytime-fitness-hk

# After reviewing the data and target environment, fetch again and write to Supabase.
pnpm import:anytime-fitness-hk --upsert
```

Each pnpm command can also be run as `node scripts/gyms/import-<name>.mjs`, for example `node scripts/gyms/import-anytime-fitness-hk.mjs --limit 2`. Separate argument values with spaces, as in `--limit 2`.

## Importers

| pnpm command | Source | Default output, relative to this directory | Automatically loaded env file |
| --- | --- | --- | --- |
| `pnpm import:247-fitness-hk` | 24/7 Fitness Hong Kong API | `247-fitness-hk-baseline.json` | `apps/web/.env.prod` |
| `pnpm import:anytime-fitness-hk` | Anytime Fitness Hong Kong API | `anytime-fitness-hk-baseline.json` | `apps/web/.env.dev` |
| `pnpm import:efx24-hk` | EFX24 branch website | `efx24-hk-baseline.json` | `apps/web/.env.dev` |
| `pnpm import:go24-fitness-hk` | GO24 Fitness branch website | `go24-fitness-hk-baseline.json` | `apps/web/.env.dev` |
| `pnpm import:hyrox-official-hk` | Official HYROX partner gym finder | `hyrox-official-hk.json` | `apps/web/.env.dev` |
| `pnpm import:lcsd-fitness-hk` | LCSD fitness room website | `lcsd-fitness-hk-baseline.json` | `apps/web/.env.prod` |
| `pnpm import:pure-fitness-hk` | PURE Fitness branch website | `pure-fitness-hk-baseline.json` | `apps/web/.env.dev` |
| `pnpm import:snap-fitness-hk` | Snap Fitness Hong Kong API | `snap-fitness-hk-baseline.json` | `apps/web/.env.dev` |

Env file paths and all CLI file paths are relative to the working directory. Env files do not override variables already set in the shell. These gym importers currently have no `--env` argument.

Writing to Supabase requires `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SECRET_KEY`. Before using `--upsert`, `--upsert-file`, or HYROX's `--repair-stale`, confirm that they point to the intended environment, especially for 24/7 and LCSD, which load `.env.prod` by default.

## Arguments

| Argument | Purpose | Supported importers |
| --- | --- | --- |
| `--out <path>` | Set the JSON output path for converted gym rows | All |
| `--upsert-file <path>` | Read converted gym rows from JSON and write directly to Supabase; use on its own | All |
| `--upsert` | Insert/update Supabase data after writing JSON | All |
| `--details-file <path>` | Read a source detail JSON array instead of fetching the website/API | All |
| `--limit <n>` | Process only the first n source entries; use a positive integer for previews | All except HYROX |
| `--details-out <path>` | Save a source detail snapshot before conversion for later replay | All except 24/7 and HYROX |
| `--district-overrides <path>` | Read manual district assignments from JSON | All except HYROX |
| `--skip-geocode` | Skip Mapbox address geocoding | EFX24, GO24, LCSD, PURE |
| `--browser` | Open source pages in local Google Chrome | EFX24, GO24 |
| `--browser-profile <path>` | Set a dedicated Chrome profile for browser mode | EFX24, GO24 |
| `--address-overrides <path>` | Correct Chinese addresses | PURE |
| `--repair-stale` | Clear incorrectly matched HYROX metadata; modifies the database | HYROX |

Supported arguments vary by importer. Follow the table above; some scripts neither reject nor apply unsupported arguments.

## Write gym JSON directly to Supabase

All eight importers support `--upsert-file <path>`. This mode writes to the database on its own, without `--upsert`. It does not fetch source websites, call Mapbox, reconvert data, or overwrite JSON. Review the file and target environment first.

```bash
pnpm import:247-fitness-hk --upsert-file data/gyms/247-fitness-hk-baseline.json
pnpm import:anytime-fitness-hk --upsert-file data/gyms/anytime-fitness-hk-baseline.json
pnpm import:efx24-hk --upsert-file data/gyms/efx24-hk-baseline.json
pnpm import:go24-fitness-hk --upsert-file data/gyms/go24-fitness-hk-baseline.json
pnpm import:hyrox-official-hk --upsert-file data/gyms/hyrox-official-hk.json
pnpm import:lcsd-fitness-hk --upsert-file data/gyms/lcsd-fitness-hk-baseline.json
pnpm import:pure-fitness-hk --upsert-file data/gyms/pure-fitness-hk-baseline.json
pnpm import:snap-fitness-hk --upsert-file data/gyms/snap-fitness-hk-baseline.json
```

Input must be a nonempty JSON array of gym rows. Each row must contain nonempty `name`, `slug`, `district_code`, and `country_code` fields. District codes must use `HK-*`, the country code must be `HK`, and slugs must be unique. Source detail snapshots and override files are not valid inputs for this mode. HYROX also requires valid official partner metadata and unique partner IDs.

Do not combine this mode with other arguments, including `--upsert`, `--details-file`, `--limit`, overrides, geocoding, browser options, `--out`, or `--repair-stale`. This prevents edited data from being converted again. Timestamps and other file data are reused. Writes still follow each importer's existing rules for preserving values when input is null, equipment inventory, submission records, and HYROX matching; they do not forcibly overwrite every existing gym field.

## Save source data and replay imports

A baseline contains converted gym rows rather than the source detail format required by `--details-file`. Do not pass `*-baseline.json` as a detail snapshot.

```bash
# Save the source snapshot and converted output.
pnpm import:pure-fitness-hk \
  --details-out /tmp/raw-pure-fitness-hk-details.json \
  --out /tmp/pure-preview.json \
  --skip-geocode

# Replay the same snapshot without fetching the source website again.
pnpm import:pure-fitness-hk \
  --details-file /tmp/raw-pure-fitness-hk-details.json \
  --out /tmp/pure-replay.json \
  --skip-geocode
```

24/7 and HYROX can read detail JSON arrays in their respective source formats but do not support `--details-out`. EFX24, GO24, LCSD, and PURE may still call Mapbox when using `--details-file`; add `--skip-geocode` for offline conversion.

## District and Chinese address overrides

District overrides are JSON objects mapping a source identifier or slug to a Gymory district code, for example:

```json
{
  "pure-fitness-kinwick-centre-kin": "HK-CW"
}
```

| Importer | Supported keys, in priority order |
| --- | --- |
| 24/7 | Store ID, slug |
| Anytime | Club number, branch website URL, slug |
| EFX24 / GO24 | Branch URL, slug |
| LCSD | Venue ID, slug |
| PURE | English branch URL, branch code, slug |
| Snap | Location number, Glofox ID, full branch URL, slug |

Overrides take precedence over automatic inference. Most importers fail if a branch's district remains unresolved. HYROX has no district override argument; update its script's district inference rules instead.

```bash
pnpm import:247-fitness-hk \
  --district-overrides data/gyms/247-fitness-hk-district-overrides.json

pnpm import:pure-fitness-hk \
  --address-overrides data/gyms/pure-fitness-hk-address-overrides.json
```

Each PURE Chinese address override value must be an object containing only a nonempty `address_zh`:

```json
{
  "pure-fitness-kinwick-centre-kin": {
    "address_zh": "中環蘇豪荷李活道32號建業榮基中心3樓"
  }
}
```

Chinese address keys are checked in this order: branch code, English branch URL, then slug. Both override types can be used together. Override files in this directory are not loaded automatically; pass the corresponding argument explicitly. Overrides apply to both dry runs and upserts.

## Mapbox and Chrome mode

EFX24, GO24, LCSD, and PURE support Mapbox geocoding. They prefer `MAPBOX_PRIVATE_TOKEN`, falling back to `NEXT_PUBLIC_MAPBOX_TOKEN`. Geocoding is skipped if no token is available; it can also be disabled explicitly with `--skip-geocode`. For permission errors, use a token with Search/Geocoding access or skip geocoding.

If Node fetch encounters a CAPTCHA for EFX24 or GO24, you can manually switch to browser mode, which requires Google Chrome installed locally:

```bash
pnpm import:efx24-hk --browser
pnpm import:go24-fitness-hk --browser

# Use a custom dedicated profile.
pnpm import:efx24-hk --browser --browser-profile .cache/efx24-import-profile
```

The default profiles are `.cache/efx24-chrome-profile` and `.cache/go24-chrome-profile`. These do not use your default personal Chrome profile. Complete any verification shown in the browser manually; scripts do not switch to browser mode automatically.

## Database write behavior

All importers except HYROX use the shared upsert helper and match existing gyms by `slug`. New gyms receive an approved `add_gym` submission. Existing gyms are updated only for substantive changes, with an approved `edit_gym_info` submission. Imported `null` values do not clear existing values, and shorter addresses contained within existing addresses do not replace more detailed ones. Equipment fields are handled through the normalized inventory RPC and recorded in an `edit_equipment` submission.

See [scripts/gyms/README.md](../../scripts/gyms/README.md) for detailed rules.

HYROX uses separate matching and write logic. It creates a gym only when no trustworthy existing match is found; successful matches update HYROX metadata only.

```bash
# Synchronize official HYROX data.
pnpm import:hyrox-official-hk --upsert

# Repair old matches whose partner IDs are incompatible with the source branch.
# This writes directly to the database.
pnpm import:hyrox-official-hk --repair-stale
```

`--repair-stale` clears HYROX metadata only for incompatible gym matches whose partner IDs still exist in the source. A missing source ID alone does not remove a gym's HYROX designation. Repairs record approved submissions and take effect without `--upsert`. Do not combine the two flags: if both are supplied, only the `--upsert` branch runs.
